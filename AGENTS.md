- Quarterly Report questions live in `src/lib/quarterlyReport.ts` (not the DB); responses store answers as JSON keyed by question id, one row per organisation per report — keeps the form editable without migrations.
- Dashboard aggregates existing API records client-side through a pure metrics module; do not add dashboard-specific storage or treat event attendance as unique beneficiaries.
- Meetings (Event Schedule) storage: the `title` column holds the Event Title; the `focus_area` column holds the Focus Area dropdown (Workforce / Labs / Surveillance). `focus_area_category` is deprecated (cleared by railway/migrations/2026-10-25-meetings-title-focus-area.sql). API/frontend field names: `eventTitle` and `focusArea`; the backend re-routes legacy payloads that send the title as `focusArea`.
